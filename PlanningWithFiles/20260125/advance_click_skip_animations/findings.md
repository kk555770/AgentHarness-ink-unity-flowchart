# 發現與紀錄：點擊推進（快速連點）與動畫強制結束

## 使用者需求（用很小孩的話）
- 你一直點很快，上一句的人物還在動、文字還在慢慢跑。
- 這時候如果直接跳到下一句，畫面就會「兩句的動作疊在一起」而壞掉。
- 所以要改成：
  - 第一下：把目前這句「直接跑到最後」（文字立刻全顯示、人物立刻到最後位置）
  - 第二下：才真的進到下一句

## 觀察到的 Console 訊息（待補）
- 目前 Console 的 Error（2 筆）：
  - `[OpsidanosInk] char.transition.steps 缺少必要動作：Appear ... OutputId=7`
  - `[OpsidanosInk] char.transition.steps 缺少必要動作：Appear ... OutputId=8`

## 初步判斷的根因（用很小孩的話）
- 角色移動/淡入淡出是用「動畫」慢慢改數字。
- 你連點很快時，下一句先跑進來，但上一句的動畫還在動。
- 目前程式會「直接停掉 coroutine」，但 UI Toolkit 的動畫本身還會繼續動，導致：
  - 角色看起來會突然跳回舊位置、再跑一次
  - 系統判斷目前畫面有哪些角色時，會跟實際畫面不同步，於是出現 `缺少 Appear` 這類錯誤

## 踩雷紀錄（避免下次再踩）
### 雷 1：跑錯測試，Unity 亂閃＋產生不該存在的場景
- 怎麼踩到：
  - 用 EditMode 測試驗證時，沒有把範圍鎖在我們自己的測試，結果 Unity 把其他套件的測試也一起跑了。
- 會發生什麼事：
  - `Assets/` 下面多出 `OffMeshLinkScene.unity` 之類的測試用場景檔（不該存在於專案）
  - `ProjectSettings/EditorSettings.asset`、`UserSettings/EditorUserSettings.asset` 被改到
  - Console 出現 `Files generated by test without cleanup.`
  - Unity 可能會因為測試引發 domain reload 等狀態切換，畫面看起來「一直亂閃」
- 怎麼避免：
  - 只跑「我們自己的測試集合」（指定 assembly / 指定 test），不要跑整包 EditMode 測試
  - 如果 Console 又出現 `Files generated by test without cleanup.`：
    1) 刪 `Assets/OffMeshLinkScene.unity` 與 `.meta`
    2) 還原 `ProjectSettings/EditorSettings.asset`、`UserSettings/EditorUserSettings.asset`
    3) 清空 Console 再重新看 Error，避免被舊錯誤干擾

### 雷 2：Unity MCP 讀 Console 的 types 參數限制
- `types` 只接受：`all` / `error` / `log` / `warning`
- 想抓 Exception 也要用 `error` 去抓

### 雷 3：有些環境 git restore 會失敗
- 可能會遇到 `.git/index.lock` 權限問題，導致 `git restore` 失敗
- 需要強制還原時，可用：`git show HEAD:<檔案路徑> > <檔案路徑>` 的方式覆蓋還原
